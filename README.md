# py2cpp — a Python → C++ source translator

`p2cpp` is a self-contained C++20 command-line tool that reads a Python source
file and emits an equivalent, compilable C++ program. It is a *source translator*
(transpiler): no Python runtime is involved, no interpreter is embedded, and
nothing is needed beyond a C++ standard library.

**By default it emits one file of direct, standard-library C++** — no runtime, no
`py::` namespace, no header. That is the point: what you get back *is* your
program, written in C++. There is also a maximum-fidelity mode (`--runtime`) that
links against a small `py::` support namespace for the constructs direct mode
cannot express.

| | default (direct) | `--runtime` (fidelity) |
| --- | --- | --- |
| Output | plain standard-library C++ | C++ over a small `py::` runtime |
| Extra files | none — one `.cpp` | `py_runtime.h` |
| Type mapping | Python types → real C++ types (`list` → `std::vector`) | Python types → `py::` containers |
| Coverage | a subset; anything it cannot translate faithfully is an **error** | wider — inheritance, `**kwargs` |
| Best for | reading, editing and shipping the C++ you get | running Python you would rather not rewrite |

```bash
./build/p2cpp script.py               # direct C++, one file
./build/p2cpp script.py --runtime     # maximum fidelity, with py_runtime.h
```

`--native` (or `-n`) is kept as an alias that also selects the default direct
mode, so older command lines keep working.

## Direct conversion (the default)

```cpp
// generated by p2cpp --native: direct C++, standard library only
#include <iostream>
#include <stdexcept>
#include <string>

long long age{};

int main() {
    std::cout << "请输入你的年龄：" << std::flush;
    std::string __line; std::getline(std::cin, __line);
    age = std::stoll(__line);
    try {
        if (age >= 18) {
            std::cout << "你已成年！" << "\n";
        } else {
            std::cout << "未成年！" << "\n";
        }
    } catch (...) {
        std::cout << "请输入一个整数" << "\n";
    }
}
```

Compile it like any other file — no include path, no extra translation unit:

```bash
c++ -std=c++20 -O2 test.cpp -o test
```

The project is the whole file: `main()` ends and the file ends. There is no
support header and no trailing runtime. Values are printed **inline** — a float
goes through `std::cout` as-is, and a list becomes a short range-`for` loop that
builds `[1, 2, 3]` — so nothing is tacked on after your code.

### Helpers are emitted only for format specs

The only thing direct mode cannot spell with a single standard-library
expression is a few `f`-string format specs. When a program uses one, a small
ordinary helper is emitted at the bottom of the file (never around `main()`):

| Helper | Emitted when | Why |
| --- | --- | --- |
| `p2cpp_bin` | `f"{x:b}"` | `std::iomanip` has no binary |
| `p2cpp_pct` | `f"{x:.1%}"` | `std::iomanip` has no percent |
| `p2cpp_thousands` | `f"{x:,}"` | `std::iomanip` has no thousands separator |
| `p2cpp_center` | `f"{x:^10}"` | `std::setw` cannot centre |

### Web scraping (`requests`, `re`, `json`, `csv`)

Direct mode can translate common scraping programs. The one thing the standard
library does not have — an HTTP client — is done through the system `curl`
(which macOS, Linux and Windows 10+ all ship), so nothing needs to be
installed and the output is still a single self-contained `.cpp`.

| Python | Becomes | Notes |
| --- | --- | --- |
| `requests.get(url)` / `.text` | `p2cpp_fetch(url)` | downloads via `curl -s`, returns the body as `std::string` |
| `re.search(pat, s).group(n)` | inline `std::regex_search` | `.group()` = whole match, `.group(1)` = first capture |
| `re.findall(pat, s)` | `p2cpp_findall(s, pat)` | a capture group returns the group (Python's rule) |
| `re.sub(pat, repl, s)` | `p2cpp_re_sub(s, pat, repl)` | `std::regex_replace` |
| `json.loads(s)` | `p2cpp_json_parse(s)` | returns `std::map<std::string,std::string>` |
| `json.dumps(d)` | `p2cpp_json_dump(d)` | serialises the map back to JSON |
| `csv.save(path, rows)` | `p2cpp_csv_save(path, rows)` | `rows` is a list of lists of strings |

A realistic example, from `examples/13_scraping.py`:

```python
import requests, re, json, csv

html = requests.get("https://example.com").text
names = re.findall('<span class="name">([^<]*)</span>', html)
csv.save("out.csv", [["商品"] + names])
print(json.dumps({"count": len(names)}))
```

Three honest limits (each is a standard-library constraint, not a bug):

* **`std::regex` has no non-greedy quantifiers.** Python's `*?` / `+?` / `??`
  are relaxed to `*` / `+` / `?`. For the common "extract the text inside a
  tag" you get the same result with a negated class: use
  `re.findall("<tag>([^<]*)</tag>", s)` instead of `.*?`.
* **JSON values are stored as strings.** `{"count": 2}` parses to `"2"`, not a
  number — call `int(d["count"])` to convert. Nested objects/arrays are not
  expanded.
* **`requests.get(...)` returns the body text directly**, so `.text` / `.content`
  are no-ops; headers, status codes, timeouts and `post()` are not translated.


A program that prints only integers, strings, floats and lists emits **no
helpers at all** — six lines of Python become fifteen lines of C++, all of them
yours:

```python
n = 0
for i in range(5):
    n = n + i
    print("i =", i, "n =", n)
print("done")
```

```cpp
// generated by p2cpp --native: direct C++, standard library only
#include <iostream>
#include <string>

long long n{};
long long i{};

int main() {
    n = 0;
    for (i = 0; i < 5; ++i) {
        n = n + i;
        std::cout << "i =" << " " << i << " " << "n =" << " " << n << "\n";
    }
    std::cout << "done" << "\n";
}
```

### Direct type mapping

| Python | C++ |
| --- | --- |
| `int` | `long long` |
| `float` | `double` |
| `bool` | `bool` |
| `str` | `std::string` |
| `list` | `std::vector<T>` |
| `set` | `std::set<T>` |
| `dict` | `std::map<K, V>` |
| `tuple` | `std::tuple<...>` |
| `None` | `std::nullopt_t` |

Control flow maps to the obvious C++ (`if`/`else`, `while`, range-`for`),
functions become templates when their parameter types differ between call sites,
and a nested `def` becomes a lambda.

Indexing is deliberately checked: every read of `xs[i]`, `s[i]` and `d[k]` goes
through `.at()`, so an out-of-range index raises `std::out_of_range` exactly
where Python raises `IndexError`. Assigning `d[k] = v` uses `operator[]`, because
Python creates the key. A division whose divisor is a literal `0` is compiled to
a `throw` carrying CPython's own message, so `1 / 0` and `1.0 % 0` behave the way
Python does rather than producing undefined behaviour.

### Classes

A `class` becomes a plain `struct` with the `__init__` body as the constructor.
Members (`self.x = ...`) become fields, methods become member functions, and
class attributes (`version = 3`) become `static` members. Call sites specialise
the constructor and method parameters the same way functions are specialised;
unlike free functions, a constructor or method never becomes a template — a
parameter whose type cannot be pinned down falls back to `long long`.

```python
class Point:
    def __init__(self, x, y):
        self.x = x
        self.y = y

    def dist(self):
        return self.x * self.x + self.y * self.y

p = Point(3, 4)
print(p.dist())
```

```cpp
struct Point {
    long long x{};
    long long y{};

    Point(long long x, long long y) {
        auto& self = *this;
        self.x = x;
        self.y = y;
    }
    auto dist() {
        auto& self = *this;
        return (self.x * self.x) + (self.y * self.y);
    }
};
```

`self` maps to `*this`, so `self.x` reads and `self.m()` calls work as in
Python. A class with a `__str__` method makes `print(obj)` call it. The one
class feature direct mode cannot express is **inheritance** — a `class
Square(Shape)` is reported as an error (use `--runtime` for that).

### What direct mode refuses

The rule is: translate faithfully, or say so. Anything direct mode cannot express
without silently changing behaviour is reported as an error and **no file is
written**, so a bad translation never slips through.

```
$ ./build/p2cpp examples/10_oop.py -o oop.cpp
p2cpp: error: line 8: native mode does not translate inheritance (`class Square(Shape)`); use the default mode instead
p2cpp: cannot translate this program faithfully; add --runtime for maximum-fidelity mode
```

The messages name the construct and the fix. The common cases:

| Message | What to do |
| --- | --- |
| `native mode cannot work out the type of 'n'; annotate it, e.g. \`n: int = 0\`` | add a type annotation — C++ needs the type |
| `native mode does not translate inheritance (…)` | use the default backend |
| `native mode does not translate \`.m()\` here` | the method is outside the core set (list/str/dict/set) |
| `\`**kwargs\` cannot be modelled in native mode` | use explicit parameters |
| `\`map()\` / \`filter()\` is not supported in an expression in native mode` | use a list comprehension |
| `cannot unpack this element into 2 names` | the element's type is not a 2-tuple |

Warnings are for constructs that *are* translated but where a Python nuance
cannot be reproduced, and are printed while a file is still written:

```
p2cpp: warning: line 35: a dict is a std::map here, so it iterates and prints in key order, not the insertion order Python uses
p2cpp: warning: line 51: the `finally` body runs inline after the try block in native mode, so it is skipped if the handler re-throws
```

### Behavioural differences to know about

These are inherent, and each one has either a warning or a clear rule:

* **Dict order.** Python dicts keep insertion order; direct mode uses
  `std::map`, which keeps key order. Iterating or printing a dict can therefore
  differ. A warning is emitted once per program. Use `sorted(d)` or iterate
  `sorted(d.items())` if the order matters.
* **`int(s)` / `float(s)` stop at the first bad character.** `int("12abc")`
  becomes `12` (via `std::stoll`) and `int("3.5")` becomes `3`, where Python
  raises `ValueError`. Direct mode keeps these as plain `std::stoll`/`std::stod`
  so the output stays one clean function with no helper; use `--runtime` if you
  need Python's exact strictness here.
* **Printed values use C++'s own formatting, not Python's `repr`.** A float
  prints as `5` (not `5.0`) and to six significant digits (`1.41421`, not
  `1.4142135623730951`); a string inside a list prints bare (`[a, b]`, not
  `['a', 'b']`). This keeps the output plain `std::cout << x` with no formatting
  helper. Use `--runtime` for Python's exact `repr`.
* **Integers are 64-bit.** `long long`, not arbitrary precision. `int("9" * 30)`
  raises `std::out_of_range` where Python returns the exact value.
* **Uncaught exceptions abort.** Python prints a traceback and exits 1; C++ calls
  `std::terminate`, so the process dies with `SIGABRT`. Both backends behave this
  way, and a program that *catches* the error (a correct `try`/`except`) is
  unaffected.
* **Set order** is `std::set` order (sorted), since Python's set iteration order
  is hash-randomised per process and cannot be reproduced even in principle.

## `--runtime` — maximum fidelity

`p2cpp --runtime` aims for the widest coverage and links against a
small `py::` support namespace. That namespace is written to a separate
`py_runtime.h` beside the generated `.cpp`, so the `.cpp` holds only your
translated program:

```
$ ./build/p2cpp test.py --runtime
p2cpp: wrote test.cpp
p2cpp: wrote py_runtime.h
```

```
$ cat -n test.cpp
 1  // generated by p2cpp -- the py:: runtime lives in py_runtime.h
 2  #include "py_runtime.h"
 3
 4  long long age{};
 5
 6  int main(int argc, char** argv) {
 7      py::init_argv(argc, argv);
 8      age = py::to_int(py::input("请输入你的年龄："));
 9      try {
10          if (age >= 18) {
11              std::cout << py::str("你已成年！") << "\n";
12          } else {
13              std::cout << py::str("未成年！") << "\n";
14          }
15      } catch (...) {
16          std::cout << py::str("请输入一个整数") << "\n";
17      }
18  }
```

This backend keeps `dict` insertion-ordered, supports classes, inheritance,
`**kwargs` and more of the standard library. It is the one to use when the goal
is to *run* the program rather than to read the C++. Pass `--single-file` if you
would rather have one self-contained file with the runtime inlined, at the cost
of ~1400 lines of library code above your own.

```
$ cat hello.py
def fib(n):
    if n < 2:
        return n
    return fib(n - 1) + fib(n - 2)

for i in range(6):
    print(f"fib({i}) = {fib(i):2d}   ratio {fib(i + 1) / max(fib(i), 1):.3f}")
```

```
$ ./build/p2cpp hello.py --run
p2cpp: wrote hello.cpp
p2cpp: wrote py_runtime.h
p2cpp: c++ -std=c++20 -O2 -o '/tmp/p2cpp_build_16807_out' 'hello.cpp'
p2cpp: ---- program output ----
fib(0) =  0   ratio 1.000
fib(1) =  1   ratio 1.000
fib(2) =  1   ratio 2.000
fib(3) =  2   ratio 1.500
fib(4) =  3   ratio 1.667
fib(5) =  5   ratio 1.600
```

## Building

`c++` is the only requirement (Clang or GCC with C++20).

```bash
./build.sh          # produces build/p2cpp
```

A CMake project is also provided for IDEs:

```bash
cmake -B build -DCMAKE_BUILD_TYPE=Release && cmake --build build
```

### On Windows

```bat
build.bat                       # produces build\p2cpp.exe
```

`build.bat` uses CMake when available (works with both MSVC and MinGW); if CMake
is not installed it falls back to compiling the five source files directly with
the first of `cl` / `g++` / `clang++` it finds. Run the test harnesses the same
way as on Unix:

```bat
tests\compare_native.bat        # direct backend (the default)
tests\compare.bat               # --runtime (fidelity) backend
```

## Usage

```
p2cpp <input.py> [options]

  -o <file>        write the C++ source to <file> (default: <input>.cpp)
  -n, --native     direct C++ (this is now the default; the flag is kept
                   for compatibility)
  --runtime        maximum-fidelity mode: emit a py:: runtime in a separate
                   py_runtime.h next to the .cpp (wider coverage: classes,
                   inheritance, **kwargs). This is the old default.
  --single-file    inline the whole py:: runtime into the .cpp instead of
                   writing py_runtime.h
  --no-runtime     do not write py_runtime.h; assume you already have it
  --stdout         write the generated C++ to standard output
  --run            compile and run the generated program immediately
  -c <compiler>    C++ compiler to use with --run (default: c++)
  --no-comments    do not turn docstrings into comments
  --check          only parse the input, do not generate code
  -h, --help       show this message
```

Examples:

```bash
./build/p2cpp script.py                          # direct C++, one file
./build/p2cpp script.py --runtime -o script.cpp  # maximum fidelity
./build/p2cpp examples/02_fizzbuzz.py --run      # transpile, compile, run
./build/p2cpp examples/04_classes.py --stdout    # inspect the C++ on stdout
./build/p2cpp game.py --runtime --single-file    # self-contained fidelity .cpp
```

## Feature overview — `--runtime` backend

| Area | Supported |
| --- | --- |
| Literals | int, float, bool, `None`, `str` (`r`/`b`/`u`/`f` prefixes, triple-quoted), list, tuple, set, dict |
| Statements | assignment (chained & unpacking), augmented assignment, annotations, `if`/`elif`/`else`, `while`(+`else`), `for`(+`else`), `break`, `continue`, `pass`, `return`, `def`, `class`, `lambda`, `try`/`except`/`finally`, `raise`, `assert`, `with`, `import`/`from … import`, `del` |
| Expressions | full Python operator precedence, chained comparisons, `in` / `not in` / `is` / `is not`, `and`/`or`/`not`, ternary `a if c else b`, slicing (incl. step), negative indexing, `*args` unpacking, walrus-free |
| Comprehensions | list, set, dict, nested `for` clauses and `if` filters; generator expressions as call arguments (`sum(x for x in xs)`) |
| Functions | default arguments, `*args`, keyword arguments at call sites, nested `def`, closures (captured by value), recursion and mutual recursion, functions as first-class values |
| Classes | `__init__`, methods, `self`, attributes, single inheritance, objects in containers |
| f-strings | `{expr}`, `{expr!r}`, and the full format spec `[[fill]align][sign][#][0][width][,][.prec][type]` (`:.2f`, `:>10`, `:^10`, `:x`, `:05d`, `:,.1%`, …) |
| Builtins | `print len range int float str repr bool abs round min max sum sorted reversed enumerate zip list tuple set map filter chr ord any all isinstance format input exit id hash factorial gcd` |
| Methods | string, list, dict and set methods (see `src/codegen.cpp`) |
| Modules | `math`, `random`, `time`, `sys` (`sys.argv`, `sys.exit`) |
| Exceptions | `ValueError TypeError IndexError KeyError ZeroDivisionError RuntimeError StopIteration` |

### Containers map onto C++ types

| Python | C++ |
| --- | --- |
| `int` | `long long` |
| `float` | `double` |
| `bool` | `bool` |
| `str` | `std::string` |
| `list` | `std::vector<T>` |
| `set` | `std::set<T>` |
| `dict` | `py::dict<K, V>` — insertion-ordered, unlike `std::map` |
| `tuple` | `std::tuple<...>` (literal) / `py::tup<T>` (built at runtime) |
| `None` | `py::NoneType` |

Types are recovered by a fixed-point inference pass over the whole program, so
generated functions are C++ templates and work for the types they are called
with. Direct mode runs the same inference, and asks for an annotation when it
cannot reach an answer.

## Testing

Two end-to-end differential harnesses run CPython, transpile with `p2cpp`,
compile the result, run it, and diff the two outputs.

```bash
./tests/compare.sh            # --runtime (fidelity) backend, every examples/*.py
./tests/compare_native.sh     # direct backend (the default)
```

```
$ ./tests/compare.sh
  passed: 12   failed: 0

$ ./tests/compare_native.sh
PASS examples/01_basics.py
...
FAIL examples/03_collections.py   (mismatch)
N/A  examples/04_classes.py       (not translatable)
...
  passed: 5   failed: 2   not translatable: 5
```

Direct mode classifies a run as `PASS`, `FAIL`, or `N/A` (untranslatable), so
"not covered yet" never hides as a failure. Either harness can be pointed at
other files:

```bash
./tests/compare_native.sh examples/01_basics.py myscript.py
```

The `examples/` directory doubles as the specification: each file exercises a
slice of the supported subset (basics, functions, closures, classes, containers,
control flow, string formatting, the standard library).

## Known limitations

### Direct mode

Listed under [Behavioural differences](#behavioural-differences-to-know-about)
above, plus the constructs it reports as errors: inheritance, non-core methods,
`**kwargs`, `map()`/`filter()` in an expression position, and any name whose
type it cannot infer without an annotation.

### `--runtime` backend

These are inherent to translating dynamically typed Python into statically typed
C++ and are reported as warnings at translation time where possible:

* **Generators / `yield`** — not supported; a warning is printed and the value is
  skipped. Use a list comprehension instead.
* **`**kwargs`** — cannot be modelled (two C++ parameter packs cannot coexist),
  so the name is declared as an always-empty mapping and a warning is emitted.
  Keyword arguments *at call sites* are passed positionally.
* **One type per name** — a variable's type is deduced from its assignments. A
  name reused for two incompatible types is a compile error. In particular a
  collection whose elements are of mixed types is unified to a common type
  (`{"n": 1, "avg": 2.5}` becomes a mapping of `double`, so `1` prints as `1.0`).
* **Set order** — sets are `std::set`, so they iterate in sorted order. CPython's
  set order is hash-randomised per process, so use `sorted(s)` when printing.
* **A list of distinct lambdas** cannot be a `std::vector` — each C++ lambda is
  its own type. Store them as separate names.
* **Multiple inheritance, metaclasses, decorators with arguments, `async`,
  `match`, nested classes, `nonlocal` rebinding** are not translated.
* **Mutual recursion** needs an inferable return type; when it is not available
  the tool assumes `long long` and says so.

## Source layout

```
src/lexer.{h,cpp}     indentation-aware tokeniser (INDENT/DEDENT, string
                      prefixes, triple quotes, implicit line continuation)
src/ast.h             expression / statement node definitions
src/parser.{h,cpp}    recursive-descent parser with Python's full operator
                      precedence; produces the AST
src/codegen.{h,cpp}   type inference, name mangling, C++ emission (default)
src/native.{h,cpp}    the direct backend: plain standard-library C++
src/prelude.h         the embedded py:: runtime (containers, formatting,
                      Python arithmetic semantics, exceptions, builtins)
src/main.cpp          command line driver
tests/compare.sh      differential test harness against CPython (default)
tests/compare_native.sh   the same, for the direct backend
examples/*.py         worked examples / regression corpus
```
